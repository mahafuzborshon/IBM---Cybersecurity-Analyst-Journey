# Notes

## Software and Application Penetration Testing

- Evaluates the security of software and web applications.
- Identifies vulnerabilities before deployment.
- Supports secure software development.
- Helps reduce application security risks.
- Can include manual and automated testing techniques.

## Scanning Code Repositories

- Reviews source code for security issues.
- Detects vulnerable dependencies.
- Identifies insecure coding practices.
- Improves code quality and security.
- Supports continuous security testing.

## GitHub and Snyk

### GitHub

- Stores and manages source code repositories.
- Supports version control and collaboration.
- Integrates with security scanning tools.

### Snyk

- Scans repositories for known vulnerabilities.
- Detects insecure dependencies.
- Provides remediation recommendations.
- Supports continuous application security.

## Reporting Phase

- Documents all penetration testing findings.
- Summarizes identified vulnerabilities.
- Includes supporting evidence.
- Assigns risk or severity ratings.
- Provides remediation recommendations.
- Delivers results to stakeholders in a clear format.

## PTES Framework

- PTES stands for Penetration Testing Execution Standard.
- Provides a structured penetration testing methodology.
- Promotes consistency across penetration testing engagements.
- Covers planning, testing, reporting, and communication.
- Helps produce professional penetration testing reports.

## Components of a Penetration Test Report

- Executive Summary
- Scope of Assessment
- Methodology
- Technical Findings
- Evidence
- Risk Ratings
- Impact Analysis
- Remediation Recommendations
- Conclusion
