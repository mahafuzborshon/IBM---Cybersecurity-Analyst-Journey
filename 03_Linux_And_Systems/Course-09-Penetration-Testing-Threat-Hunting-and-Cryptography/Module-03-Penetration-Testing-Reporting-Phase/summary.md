# Module 03: Penetration Testing Reporting Phase

In this module, I learned that the reporting phase is one of the most important parts of a penetration test. Even if vulnerabilities are successfully identified, the assessment provides little value unless the findings are documented clearly and communicated to stakeholders.

I first explored software and application penetration testing, where I learned how security professionals evaluate applications to identify vulnerabilities that could affect confidentiality, integrity, and availability. I also learned that application security testing should be integrated throughout the software development lifecycle.

Another interesting topic was scanning code repositories. I learned how developers and security teams can analyze source code repositories to detect security issues before software is deployed. Through the optional GitHub and Snyk labs, I gained an understanding of how automated code scanning tools can identify vulnerable dependencies and coding weaknesses.

The reporting phase taught me how penetration testers organize their findings into professional reports. I learned that a good penetration testing report includes an executive summary, technical findings, evidence, risk ratings, and practical remediation recommendations so organizations can prioritize security improvements.

I also explored the PTES (Penetration Testing Execution Standard) Framework and learned how it provides a structured methodology for conducting and reporting penetration tests. The framework helps ensure consistency, professionalism, and complete documentation throughout an engagement.

Overall, this module showed me that technical skills alone are not enough for a penetration tester. Clear reporting, proper documentation, and actionable recommendations are essential for helping organizations understand and remediate their security risks.
